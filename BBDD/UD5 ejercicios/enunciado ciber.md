Centro de Operaciones de Seguridad (SOC)

Una empresa de ciberseguridad dispone de un Centro de Operaciones de Seguridad (SOC) encargado de monitorizar incidentes de seguridad de diferentes organizaciones clientes.

El SOC está dividido en varios equipos especializados de manera que cada equipo se encarga únicamente de un área de seguridad (respuesta a incidentes, análisis de malware, gestión de vulnerabilidades, inteligencia de amenazas, etc.), y cada área es gestionada por un único equipo.

Cada equipo está compuesto por varios analistas. Cuando se detecta un incidente de seguridad, se asigna a un analista para que lo investigue y gestione durante todo su ciclo de vida. Dicho analista realiza un análisis, determina la gravedad del incidente y propone las acciones de mitigación correspondientes. Un analista puede gestionar varios incidentes simultáneamente.

Además del analista responsable, otros especialistas pueden colaborar en la resolución del incidente. Un especialista puede colaborar en varios incidentes y un incidente puede contar con la participación de varios especialistas.

Las organizaciones clientes poseen diferentes activos tecnológicos (servidores, estaciones de trabajo, aplicaciones web, bases de datos, dispositivos de red, etc.). Cada incidente afecta a un único activo, aunque un activo puede verse afectado por múltiples incidentes a lo largo del tiempo.

Además de estas cuestiones, hay que tener en cuenta:

De cada equipo interesa saber:

Código de equipo (único).
Área de seguridad que gestiona.
Número de analistas que lo componen.

De cada analista interesa saber:

Identificador profesional (único).
Nombre.
Correo electrónico.
Equipo al que pertenece.
Incidentes que tiene asignados.

De cada especialista interesa saber:

Código de especialista (único).
Nombre.
Especialización.
Incidentes en los que colabora.

De cada organización cliente interesa conocer:

Código de cliente (único).
Nombre de la organización.
Sector empresarial.
Persona de contacto.

De cada activo interesa conocer:

Identificador de activo (único).
Nombre.
Tipo de activo.
Dirección IP.
Organización propietaria.

De cada incidente interesa conocer:

Código de incidente (único).
Fecha de detección.
Descripción.
Nivel de gravedad.
Estado (abierto, en investigación, mitigado o cerrado).
Analista responsable.
Activo afectado.
Acciones de mitigación propuestas.
Especialistas colaboradores.

Cuando un incidente se cierra definitivamente, se conserva su información para futuras auditorías y análisis forenses.
